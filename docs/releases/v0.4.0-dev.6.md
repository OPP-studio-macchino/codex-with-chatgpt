# C2C Auto-loop v0.4.0-dev.6 — technical preview

This is a prerelease of the audit-driven product refactor, not a stable or generally validated release.
The release is cut from the isolated `feat/product-ux-no-mention-20260930` branch. It does not merge
the default branch or update/restart the author's running C2C service.

## Included

- Outcome-oriented MCP descriptions so local development requests need not name C2C/Codex when tools are available.
- Explicit workspace-bound operations and Codex tasks, with OAuth anchor isolation and existing-run continuity.
- Durable start/terminal task records, status and safe handoff after bridge restart without blind replay.
- Native owner-approved project registration without JSON editing or bridge restart.
- Guarded reconciliation of interrupted tasks; original outcomes remain unknown and original tasks are not replayed.
- Per-target journal/lock isolation across bridge anchors, plus a read-only legacy-layout upgrade check.
- Matching bridge/Tunnel startup settings generated and verified against one release manifest.
- Previously local bounded network-image fetch and Desktop integration, retaining their existing permission boundaries.

## Validation and its limits

The candidate passed 53 Vitest files / 430 tests, typecheck, build and Skill validation on the author's Mac
on 2026-09-30. Python startup-diagnostic and bundle tests are invoked from Vitest wrappers, not added to that total.
Release hygiene changes add checks for preserving owner-supplied audio references and are revalidated before tagging.

One isolated real-Mac acceptance completed native folder selection → owner approval → registration → actual
Codex marker-file read → bridge close/reopen → saved-result recovery. Its private evidence is retained locally,
not shipped. Most other owner decisions in regression tests use explicit fixtures/mocks.
A limited static review of the upgrade-layout change reported no new P0/P1 finding; this is not a complete product audit.

## Known limitations / not claimed

- Fresh-chat no-mention selection and real ChatGPT two-chat acceptance are not complete. Metadata cannot expose
  tools that the ChatGPT host does not provide. ChatGPT stream errors are not guaranteed to disappear.
- Live cutover, real Mac reboot, and rollback execution are not validated by publishing this prerelease.
- The actual interrupted-task reconciliation approval UI still needs separate owner-interaction acceptance.
- `user_input_required` question/reply/resume support and temporary read-only grants are not included.
- First-install setup, network-permission management/diagnostics, and general-user distribution still need work.
- Legacy anchor-keyed task journals stop with `TASK_JOURNAL_MIGRATION_REQUIRED`; they are not silently
  migrated, deleted, or reinterpreted as empty history. Preserve records and migrate offline.
- Public source and artifacts contain no owner credentials, generated host launch settings, private run logs,
  or personal completion audio. An existing absolute sound-file setting is retained, not bundled.

## Try this exact tag

```sh
git clone --branch v0.4.0-dev.6 --depth 1 https://github.com/OPP-studio-macchino/codex-with-chatgpt.git
cd codex-with-chatgpt
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
corepack pnpm validate:skill
node bin/c2c.js --help
```

Review dependencies and consent boundaries before installing. The optional release archive contains source,
lockfile and built JavaScript, but no dependencies or configured owner credentials. Install dependencies
explicitly; do not point a new service at active production state or replace LaunchAgents without review.
Consult the existing README for explicit transport/execution setup and `docs/refactor/` for the new flows.
